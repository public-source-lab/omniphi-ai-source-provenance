# Domain and Technical Infrastructure Investigation

## Purpose

This document records technical infrastructure evidence concerning websites involved in the OmniPhi information-distribution investigation.

The objective is to determine whether apparently separate websites have independently operated infrastructure or whether there are technically verifiable relationships between them.

Technical similarities alone do not establish common ownership.

## Technical Evidence Categories

Each domain should be examined for:

### Domain Registration

- Registration date
- Registrar
- Registration status
- Nameservers
- Historical nameservers
- Domain ownership information where publicly available

### DNS

- A records
- AAAA records
- MX records
- TXT records
- CNAME records
- Historical DNS records

### Hosting

- IP address
- Autonomous System Number
- Hosting provider
- CDN
- Reverse proxy
- Historical hosting

### TLS / Certificates

- Certificate issuer
- Certificate dates
- Subject Alternative Names
- Certificate transparency records

### Website Technology

- CMS
- Frameworks
- Plugins
- JavaScript libraries
- CDN
- Analytics
- Tag managers
- Advertising systems

### Tracking Identifiers

Look for:

- Google Analytics identifiers
- Google Tag Manager identifiers
- Meta Pixel identifiers
- Advertising identifiers
- Other unique tracking identifiers

A shared commercial technology is weak evidence.

A unique identifier appearing across apparently unrelated sites can be substantially stronger evidence of a common administrative or commercial relationship.

### Content Infrastructure

Compare:

- HTML structure
- CSS files
- Image paths
- Image filenames
- Article IDs
- Author IDs
- RSS feeds
- Sitemap structure
- Canonical URLs
- Open Graph metadata
- Schema.org metadata

## Evidence Standard

Technical similarities should be classified according to strength.

### Weak

Examples:

- Same hosting company
- Same CDN
- Same CMS
- Same WordPress theme
- Same registrar

These are common across unrelated websites.

### Moderate

Examples:

- Unusual identical templates
- Identical custom JavaScript
- Identical uncommon plugins
- Repeated unique metadata
- Shared unusual advertising infrastructure

These warrant further investigation.

### Strong

Examples:

- Same unique analytics identifier
- Same unique advertising identifier
- Shared administrative infrastructure
- Direct ownership documentation
- Explicit common ownership
- Identical private infrastructure
- Other evidence uniquely connecting administration of the sites

## Important Limitation

An IP address, nameserver, hosting provider, CMS, or other commercially common technology should not be presented as proof of common ownership.

Infrastructure evidence should be evaluated alongside:

- Corporate records
- Domain records
- Contact information
- Publication records
- Author information
- Legal pages
- Financial relationships
- Direct statements of affiliation

## Interpretation

The purpose of this investigation is not to find technical similarities and then infer coordination.

The purpose is to determine whether independently verifiable technical evidence can establish relationships that are otherwise difficult to observe from published content.

Negative findings are also important.

If two sites have clearly independent infrastructure, that should be recorded as evidence against a hypothesis of common technical administration.
